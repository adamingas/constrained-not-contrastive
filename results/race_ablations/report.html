What do the system prompt and chat template contribute?

Seven Qwen prompt variants on the same 200 RACE-M test questions, with no-passage controls and 20 option-reversal audits per variant. The original Qwen prompt and CLM are rerun in the same process, interleaved randomly. Total: 3,340 predictions.

Removing both the system instruction and chat template, while retaining a two-token Answer: cue, scored 90.5% versus 87.0% for the original. Its median paired latency ratio was 0.920, a 8.0% reduction relative to the original on matched questions. Literal stripping without the cue scored 59.0%. The small apparent improvement over original accuracy needs fresh-data validation; the exact paired McNemar p-value is 0.065, before multiple-comparison adjustment.

Exact interventions

  • Original: the prior 21-token system instruction, Qwen's normal chat template and non-thinking assistant prefix.
  • Short system: replace the instruction with Reply with A, B, C, or D., retaining the template.
  • No system: remove the system message entirely; retain the user message and non-thinking assistant prefix. The tokenizer inserts no replacement system instruction.
  • No template: retain the full instruction as plain text before the unchanged user body, remove role delimiters and the assistant/thinking prefix, then append Answer: as a conventional completion cue.
  • Neither: remove the instruction and template; retain the unchanged user body plus Answer:.
  • Literal raw controls: repeat both raw versions without adding the answer cue. These end immediately after the final option's text.

The answer cue costs two tokens on the first example. It is reported explicitly because deleting a chat template also deletes its assistant answer boundary. Testing both raw endings avoids hiding that choice inside a template ablation. The passage, question, four choices, labels and original option order are identical across primary conditions. CLM retains the released head and canonical raw state/action inputs.

The primary experiment always restricts the next token to exactly the bare letters A/B/C/D, matching the original benchmark. Removing the chat template can change the model's preferred continuation format. For a secondary diagnostic, the same hidden state is scored with either a bare letter or a single-leading-space letter token allowed; token-alias probabilities are summed per answer. This requires no additional backbone pass and does not replace primary scores. Full-vocabulary diagnostics use the first ten frozen test cases, independent of correctness. All diagnostics run after the primary decision timer stops.

Timing and reproducibility

BF16 Qwen3-8B on the same M4 Max/MLX setup; thinking disabled, one output-token decision, no generation loop. Each full state is recomputed. No Qwen prefix, document or whole-request cache is reused. CLM action embeddings are cached outside timed decisions. Methods and no-passage controls are randomly interleaved within each question. Latencies include prompt construction, tokenization, prefill and selecting the allowed label; GPU outputs are materialized before stopping the timer. Model loading, CLM action setup and secondary output diagnostics are excluded. There is one timed call per condition on each of 200 different questions, not repeated identical-prompt microbenchmarks.

The new original-prompt run agrees with 200/200 prior Qwen choices; CLM agrees with 200/200 prior choices. Small BF16 differences can affect close decisions. Compare latency within this new interleaved run rather than attributing differences between separate sessions entirely to prompt changes.
